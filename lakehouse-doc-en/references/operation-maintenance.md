## Task Operations and Instance Operations

The Operations Center provides management operations for tasks and instances. The tasks managed by the Operations Center include manually triggered tasks and periodically scheduled tasks, along with their corresponding instances, for centralized management.

### Task Operations
#### Task List
Click "Task Operations" in the left navigation to enter the task list page. The task list provides a summary display of tasks in all workspaces under the currently activated services.
![](.topwrite/assets/image_1668864727926.png)

##### Task List Content
In the list, you can view key attributes such as task name, task ID, workspace, task status, task type, etc.

##### Task List Operations
In the task list, you can select single or multiple tasks for quick operations.
![](.topwrite/assets/image_1668864740236.png)
Single Task
- Pause
  - Can only be operated on tasks that are not in a paused state. After the operation, the task's scheduling attribute will be set to "Pause Scheduling," meaning no more task instances will be generated or run.
- Start
  - Can only be operated on tasks that are in a paused state. After the operation, the task's scheduling attribute will be restored to "Normal Scheduling," meaning task instances will be generated and run.
- Delete
  - This operation will take the task offline from the Operations Center, reverting the task to the "Unsubmitted" state in the file.
Multiple Tasks, Batch Operations
- Batch Start
  - Batch operation on selected tasks, restoring the task's scheduling attribute to "Normal Scheduling."
- Batch Pause
  - Batch operation on selected tasks, setting the task's scheduling attribute to "Pause Scheduling."

##### Task List Filtering
At the top of the task list, you can filter tasks based on their attributes as needed.
- More Filters
  - Clicking this will expand more filtering options.
![](.topwrite/assets/image_1668864750584.png)
- Reset Filters
  - Clicking this will reset and clear all currently given filtering conditions.
- Refresh
  - Refresh the list to retrieve it again based on the given conditions.

#### Task Details
From the task list, click the task name link to enter the task details page. On this page, you can view basic information, upstream and downstream dependency graphs, task instances, and code.

##### Basic Information
In this area, you can view the basic information of the task.
![](.topwrite/assets/image_1668864765633.png)

##### Dependency Graph
In the dependency graph, you can view the directly upstream tasks that the current task depends on and the directly downstream tasks that depend on it.
- Search
  - By providing a keyword of the task name or task ID, you can quickly locate the task node on the graph. The matching method used is "contains."
- Refresh
  - Clicking this will reload the entire dependency graph.
![](.topwrite/assets/image_1668864772611.png)

##### Task Instances
In the task instance area, all task instances generated by the current task will be displayed for all time ranges.
![](.topwrite/assets/image_1668864779204.png)
For a single task instance, you can perform basic control operations:
- Stop
  - Can be operated to stop instances that are not running.
- Rerun
  - Can be operated to rerun instances that have reached a terminal state, meaning the instance will be run again.
Code
The node code area displays the latest version of the code for the current task.
![](.topwrite/assets/image_1668864785641.png)

##### Task Operations
On the task details page, you can pause, start, or delete the task, with the same meaning and effect as the operations provided in the list.
- Pause
  - Can only be operated on tasks that are not in a paused state. After the operation, the task's scheduling attribute will be set to "Pause Scheduling," meaning no more task instances will be generated or run.
- Start
  - Can only be operated on tasks that are in a paused state. After the operation, the task's scheduling attribute will be restored to "Normal Scheduling," meaning task instances will be generated and run.
- Delete
  - This operation will take the task offline from the Operations Center, reverting the task to the "Unsubmitted" state in the file.

### Instance Operations
#### Instance List
Click "Instance Operations" in the left navigation to enter the instance list page. The instance list provides a summary display of task instances in all workspaces under the currently activated service instances.
![](.topwrite/assets/image_1668864794756.png)

##### Instance List Content
In the list, you can view key attributes such as instance ID, corresponding task name, instance type, workspace, instance status, scheduled time, execution time, and completion time.

##### Instance List Filtering
At the top of the instance list, you can filter instances based on their attributes as needed.
- More Filters
  - Clicking this will expand more filtering options.
![](.topwrite/assets/image_1668864807533.png)
- Reset Filters
  - Clicking this will reset and clear all currently given filtering conditions.
- Refresh
  - Refresh the list to retrieve it again based on the given conditions.

##### Instance List Operations
In the instance list, you can select single or multiple task instances for quick operations.
![](.topwrite/assets/image_1668864815341.png)
Single Task Instance
- Pause
- Pause
  - Only operable for task instances that are not in a paused state. After the operation, the scheduling attribute of the task instance will be set to "pause scheduling", meaning the task instance will no longer be scheduled to run.
- Resume
  - Only operable for task instances that are in a paused state. After the operation, the scheduling attribute of the task instance will be restored to "normal scheduling", meaning the task instance will run according to the scheduled time.
- Terminate
  - Only operable for task instances that are running. After the operation, the task instance will be terminated, and its status will be set to failed.
- Rerun
  - Only operable for task instances that have completed running. After the operation, the task instance will be rerun.
- Set to Success
  - Only operable for task instances that have failed. After the operation, the task instance will be forcibly set to success. This can be used in emergency maintenance scenarios where it is determined that even if the current task instance fails, it does not affect the correctness of downstream task data, thus removing the blockage for downstream task instances.

Multiple task instances, batch operations
- Pause
  - Same as single operation. Note that it is only operable for task instances that are not in a paused state.
- Resume
  - Same as single operation. Note that it is only operable for task instances that are in a paused state.
- Terminate
  - Same as single operation. Note that it is only operable for task instances that are running.
- Rerun
  - Same as single operation. Note that it is only operable for task instances that have completed running.
- Set to Success
  - Same as single operation. Note that it is only operable for task instances that have failed.

#### Instance Details
From the instance list, click the instance ID link to enter the details page of the task instance. On this page, you can view basic information, upstream and downstream dependency graphs, task instances, and code.

##### Basic Information
In this area, you can view the basic information of the task instance.
![](.topwrite/assets/image_1668864827160.png)

##### Dependency Graph
On the dependency graph, you can view the direct upstream task instances that the current task instance depends on, to quickly determine whether the current task instance can be normally scheduled.
- Search
  - By providing a keyword of the task name or instance ID, you can quickly locate the task instance node on the graph. The matching method used is "contains".
- Refresh
  - Click to reload the entire dependency graph.
![](.topwrite/assets/image_1668864833952.png)

##### Code
The code area displays the version of the code used by the current task instance at runtime. Note that this may not be the latest version of the task code.
![](.topwrite/assets/image_1668864841562.png)

##### Execution Log
The execution log area displays all logs of the current instance execution, including logs generated after the task instance is rerun. Click the + icon on the left side of the list to expand and view detailed content.
![](.topwrite/assets/image_1668864848251.png)

##### Operation Log
The operation log area displays records of operations performed on the current instance.
![](.topwrite/assets/image_1668864855135.png)

##### Instance Operations
On the task instance details page, you can perform pause, resume, terminate, rerun, and set to success operations on the task instance. The meanings and functions are the same as the operations provided in the list.
