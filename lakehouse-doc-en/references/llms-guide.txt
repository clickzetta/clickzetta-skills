# Singdata Lakehouse — User Guide

- [Object Model](https://singdata.com/documents/object_model_design): Comprehensive overview of the Lakehouse object model, describing the Instance/Workspace/Schema hierarchy and categorizing objects: catalogs, tables, volumes, connections, pipes, streams, indexes, partitions, functions, and synonyms.
- [Organization Hierarchy](https://singdata.com/documents/org-hierarchy): Describes Lakehouse's four-tier organization structure (Instance, Workspace/Catalog, Schema, data objects), with tier descriptions and recommendations on when to use multiple workspaces, schemas, and external catalogs.
- [Workspace](https://singdata.com/documents/om-workspace): Describes workspaces as the resource organization and isolation unit in Lakehouse, covering capabilities, the instance/workspace/schema hierarchy, and built-in workspace roles and permissions.
- [Schema](https://singdata.com/documents/om-schema): Explains Schema as a workspace namespace for logical grouping and permission isolation of data objects, covering purposes, hierarchy, and common operations like CREATE SCHEMA and USE SCHEMA.
- [External Schema](https://singdata.com/documents/external-schema): Overview of EXTERNAL SCHEMA for querying external metadata services like Hive Metastore, covering benefits, catalog relationship, supported sources, billing, privileges, limitations, and OSS connection examples.
- [EXTERNAL CATALOG](https://singdata.com/documents/external-catalog-summary): Overview of External Catalog (preview), a secure object mapping external databases like Hive for read-only federated queries and data import, covering use cases, setup steps, and admin permissions.
- [External Catalog Concept](https://singdata.com/documents/external-catalog-concept): An explanation of the External Catalog federated query feature, covering its read-only no-copy access to external sources like Hive, Databricks, and Snowflake Iceberg, architecture, and supported data sources.
- [Data Tables](https://singdata.com/documents/table-overview): Overview of Lakehouse data table types — standard, dynamic, view, materialized view, external, and semantic — with selection guidance, Parquet columnar storage, partitioning, bucketing, and cost impacts.
- [Regular Tables](https://singdata.com/documents/om-table): An overview of the Table object as the basic data storage unit, covering Parquet columnar storage, primary key support, Time Travel, hidden partitioning and bucketing, suitable scenarios, and a creation example.
- [Dynamic Table](https://singdata.com/documents/om-dynamic-table): Explains Dynamic Tables as incremental-computation objects, comparing them to materialized views, views, and tables, and detailing incremental principles, refresh scheduling, and a quick example.
- [Views](https://singdata.com/documents/om-view): Explains Views as zero-storage virtual tables saving SQL definitions, comparing them with materialized views and dynamic tables and demonstrating JOIN encapsulation, column hiding, and row-level permission isolation.
- [Materialized View](https://singdata.com/documents/materializedview): A materialized view is a special database object that can periodically cache query results to improve performance and efficiency.
- [External Table Overview](https://singdata.com/documents/external-table-guide): Introduces Lakehouse external tables for querying external data (Kafka, Delta Lake, Hudi), covering differences from external schemas, OSS/GCS connection examples, billing, and permissions.
- [Delta Lake External Table](https://singdata.com/documents/delta-lake): Describes accessing Delta Lake format data via external tables, with examples of creating a storage connection and a partitioned Delta external table, plus dropping external tables.

- [Lance External Table](https://singdata.com/documents/lance_guide): Guide to reading Lance ML-oriented columnar datasets on OSS as external tables for vector similarity search, covering SQL commands, prerequisites, creating storage connections and Lance external tables, and distance functions.
- [Kafka External Table](https://singdata.com/documents/kafka-external-table): Preview guide to creating Kafka external tables, covering the Kafka storage connection syntax and external table definition with topic, partition, offset, and value fields plus consumer options.
- [Semantic View](https://singdata.com/documents/om-semantic-view): Overview of Semantic View, a logical data model object providing a semantic abstraction layer with logical tables, dimensions, metrics, and filters for consistent metric definitions and a lower query barrier.
- [File Storage](https://singdata.com/documents/volume-overview): An overview of Volumes for file storage in Lakehouse, covering internal and external Volume types, selection guidance, core mechanisms, and the Volume file protocol formats.
- [Internal Volume](https://singdata.com/documents/om-internal-volume): Guide to using Internal Volume storage covering User Volume, Table Volume, and Named Volume types, with SQL commands for viewing, querying, uploading, downloading, and deleting files.
- [Named Volume](https://singdata.com/documents/om-named-volume): Explains Named Volumes, internal user-created Volumes stored in Lakehouse with user-managed lifecycle and shareable permissions, comparing Volume types and showing creation and file operations.
- [External Volume](https://singdata.com/documents/om-external-volume): Explains External Volumes that mount external object storage (OSS/COS/S3) to query, import, and export files in place, with prerequisites and CREATE EXTERNAL VOLUME syntax and parameters.

- [Data Pipelines](https://singdata.com/documents/pipe-overview): An overview of Pipe (continuous ingestion) and Table Stream (change capture) objects, covering Pipe types, object storage ingestion setup, and the two ingestion modes.
