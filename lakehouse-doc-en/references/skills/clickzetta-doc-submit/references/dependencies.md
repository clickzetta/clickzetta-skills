# SUMMARY 与文档引用影响

## 检查轻重和提交门槛

使用现有 `docs_submit.py check`，读取本次基准与 Git index；提交后加 `--revision HEAD` 可检查真实提交。检查只读，不自动改文档或导航，不需要新依赖、服务、持久索引或知识图谱。

| 对象 | 检查与处理 |
| --- | --- |
| SUMMARY | 必需检查。本次新增漏登记、改名 / 删除后链接失效、新增重复或越出语言目录等错误阻断提交；维护现有层级和位置，不重新生成全目录 |
| 其他文档引用 | 可选建议。尽量定位明确链接，用户选择修复时再改；未处理也可继续提交 |
| LLM 索引 | 依据 SUMMARY 给可选建议，规则见 [LLM 索引维护](llms-index.md) |

保留既有历史问题提示及明确的 `--allow-unlisted` 导航例外，不借本次提交补齐所有历史未注册文档。SUMMARY 结构检查能核对精确 Git 路径、大小写、目标存在性和登记情况；章节位置和导航文案仍结合正文、相邻条目及使用者意图审阅，不能承诺自动判断语义位置。

## 按变更触发

- 新增页面：检查 SUMMARY 登记并建议核对相关入口；不为寻找潜在关联而扫描全库正文。
- 改名 / 移动 / 删除：用 Git 文本搜索在同语言已跟踪内容（含未注册页面）中预筛旧文件名和无扩展名路由，再解析候选 Markdown 中仍引用旧目标的链接；含编码、HTML 实体或转义的文本保守纳入候选。移动页面同时核对自身相对链接。
- 仅修改正文：检查修改中新增的明确链接，不扫描全库寻找语义依赖。仅修改标题引发的锚点变化由代理按需补查。
- Git 未识别的大幅改写加改名可能显示为删除加新增：仍能提示旧路径引用，但不猜测新旧页面对应关系；需代理核实。

`document_dependency_review` 提醒本次存在结构变化，`dependency_reviews` 记录触发文件、是否扫描入站链接及实际解析的候选 Markdown 数。`document_deleted_in_use` / `document_link_missing` 均带 `optional: true`；发现问题也不影响 `ok` 或退出码。既有图片完整性检查仍按原规则执行。

## 链接覆盖

解析 Markdown 普通和引用式链接、HTML `<a href>`、相对路径、以 `/` 开头的语言根路径，以及对应语言官网 `/documents/…` URL；可识别无 `.md` 的页面路由并解码路径。排除代码块和行内代码，不把其他站点或另一语言官网当作当前仓库文件。

输出来源文档、`line`、原始 `url`、目标 `target`；行号用于定位所在语法块，跨行 Markdown 的多个链接可能共享块起始行。Git 明确识别改名时提供 `suggested_url`，保留查询参数、锚点和链接风格。纯删除无已知替代文档时建议移除链接或人工选择替代页，不自动重定向。

不校验锚点是否存在、不验证官网部署和 HTTP 状态，不保证发现正文里的隐含语义关系、纯文本文件名、脚本生成链接或全部自定义路由。因此只报告“已发现的明确引用”，不能报告“所有依赖均已修复”。

## 为什么默认不用概念图谱

本地 `clickzetta-doc-search` 的图谱用于概念检索和关联推荐，不是由当前待提交内容实时生成的完整链接清单。增删改名检查更需要精确路径和实际 Git 快照，使用本地解析可避免图谱过期、缺失或重建成本。查找内容相近的替代页面时可按需用已有图谱辅助，但最终以正文和路径核实，不将图谱纳入提交必需依赖。

需要人工补查字面引用时可用 Git 自带搜索，无需安装工具。例如在 Gerrit 中文仓库检查暂存内容：

```bash
git grep --cached -n -I -F -e 'old-name.md' -e '/documents/old-name' -- clickzetta-doc-cn
```

英文使用 `singdata-doc-en`，旧库使用对应仓库根路径。搜索结果只是候选，不能全局替换同名文件、示例代码或外站 URL。旧库检查仍按 [双份提交](dual-remote.md) 将基准和暂存快照映射到隔离的语言前缀检查环境。
