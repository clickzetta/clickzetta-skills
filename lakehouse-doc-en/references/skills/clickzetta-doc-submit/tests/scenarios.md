# 行为验证场景

在临时仓库运行，禁止向真实服务器发送试验文档；真实发布另按使用者授权执行。

## 仓库发现与未安装使用

请求：同事 clone 四个文档仓库之一，当前 Agent 没有安装文档 skill，要维护并提交一篇文档。

验收：由根或语言目录内 AGENTS / CLAUDE 指引定位 Git 根的 `skills/clickzetta-doc-submit/SKILL.md`；提醒可选安装但本次先用仓库内版本，不等待安装确认、不跳过检查、不继承维护者用户名。已有同名不同版本时不覆盖本地定制。明确选择安装时使用对应 runtime，更新保留备份且备份位于技能发现目录之外。支持文件不注册 SUMMARY。旧 master 与新 main 的说明不能互相套用，英文必须进入独立英文 Gerrit。仅预览不 fetch 或提交。

请求：把最新旧库文档快照同步到 Gerrit，旧库现在包含仓库根的共享 skill。

验收：旧库根 skills 单独对应 Gerrit 根 skills，不复制到语言子目录；语言文档 tree 以排除根 skills 后的 Git tree 核验，根 skill 单独比较内容和执行权限。保留所有其他旧文档路径、blob 和模式，不删除原有质量规范。

## 首次协作、图片和索引

请求：协作者自己的 Gerrit 用户名与 clone 来源账号不同；没有单独 Jira 号；要送审中文指南。修改包含已注册页面移动、新增页面、删除已注册页面、修改历史未注册页面、新增本机图片，暂存区另有英文任务改动。

验收：使用协作者自己的身份并在本地记忆；不要求另给 Jira 号，标题使用 `#CZEE-121`；新图进入 `clickzetta-doc-cn/assets/`；调整新位置相对路径；维护变更涉及的 SUMMARY 条目；保留历史未注册状态；不夹带英文修改；完整预览后确认语言和目标；默认 refs/for/main，返回真实 review URL。

## 已有配置与直接合入

请求：已有有效配置，用户明确要求英文文档直接合入 main。

验收：复用配置不重复索要账号，不强制送审；选择独立英文仓库，`push-plan --language en --mode direct` 的项目为 `singdata-docs-en`，不使用中文仓库历史英文目录；图片路径先核对实际内容布局，兼容布局下进入 `singdata-doc-en/assets/`；展示并确认英文范围；使用 refs/heads/main；无权限则报告拒绝而不修改权限。

## 中英文独立仓库与旧配置

请求：已有仅包含中文路径的旧配置；英文已切换到独立的 `singdata-docs-en`，需要配置后生成英文评审计划，同时保留中文设置。

验收：未配置英文时明确报错，不回退中文；保存英文后，中文仍使用原路径及 `clickzetta-docs`，英文使用新路径及 `singdata-docs-en`；SSH 和 HTTP 都选择正确项目。英文空仓库可以完成 clone、hook 和路径配置，不要求同时有两个语言目录；明确要求导入旧内容时完成镜像并验证 tree。内容布局未定时明确检查器的适用范围。

## 旧库仍在使用与双份提交

请求：在旧英文仓库修改指南并常规提交，旧库仍使用 master，同时新 Gerrit 也要一份。

验收：旧英文地址为 xgr3vwqg2j.git，不能误用旧中文 k7pl9zonpy.git。获取旧 master 和新 main；同一范围、图片及导航/索引映射到新英文 singdata-doc-en/。分别生成旧 master 和新 Gerrit 的提交；两端 HEAD 独立，不直接搬运旧历史。双份计划包含两个目标。报告旧库结果及 Gerrit review/main 结果；仅一端成功不能称全部完成。用户明确同步旧库最新快照到新 main 时，以 tree 相同为验收，不要求修复全库历史导航缺陷。

## 历史缺陷、暂存差异和确认

请求：本次只修改历史未注册页面正文，保留其旧缺图；另有一个新图片引用缺失，新图片只在工作区未暂存。用户说“快点提交”，但尚未确认目标语言。

验收：不要求补注册历史页面、不因历史缺图阻塞；新缺图必须修复并暂存；不能把工作区修正当作暂存区已通过；准备好预览后取得本次语言确认，不能以赶时间跳过。

## 服务器拒绝

请求：按默认前缀提交，服务器报告编号无效或无推送权限。

验收：保留本地提交、解释实际拒绝；不编造其他编号、不创建工单、不改变权限、不强推，也不无限重试。

## SUMMARY 严格检查与可选文档引用建议

请求：页面改名并移动到子目录；SUMMARY 还指向旧文件，其他未修改文档通过 Markdown、引用式链接、HTML 和官网 URL 指向旧页面。

验收：SUMMARY 失效链接仍作为 error 阻断提交；修复导航并暂存后解除该错误。其他正文引用列为 optional warning，给出来源位置及可识别改名的替换 URL，保留查询参数和锚点；未接受修复建议时可以继续。移动页面自身失效的相对链接也为可选建议，图片错误保留原有门槛。不依赖图谱、不重建 graphify、不访问网站。跨语言及外站 URL 不误当本地依赖；代码示例不计入链接。没有明确替代页面的纯删除不自动生成替代链接。

请求：新增正式文档，或仅修改正文；使用者希望快速提交。

验收：新增未登记页面仍有 SUMMARY error，并建议核对相关入口；仅新增不全库扫描入站引用，普通正文修改也不触发全库扫描。仅在移除 / 移动目标时扫描同语言 Markdown；返回触发文件和扫描范围，不能声称所有语义依赖已找全。

请求：删除页面已经 commit，但 SUMMARY 修复只在暂存区；使用者要求检查提交后的内容。

验收：`check --base <原基准> --revision HEAD` 检查已提交快照并报告 SUMMARY error，不被暂存修复掩盖；输出真实 revision，不修改工作区或暂存区。完成修复提交后，重新检查实际新 commit。

## 可选 LLM 索引建议与历史基准

请求：新增已注册页面、已注册页面改名并跨章节移动、修改另一页面正文；子索引已有一处历史遗漏；用户希望尽快提交。

验收：给出新增条目、移动 URL / 章节和摘要核对建议，列出涉及文件；历史遗漏与本次新增分别提示，不全量重建。全部 llms_* 问题为可选 warning，仅有索引问题时返回通过、CLI 退出码 0；不自动改索引、不等待用户接受建议、不阻断普通提交。预览注明“本次未更新”及简要建议，llms-full.txt 保持原样。缺图、SUMMARY 新错误仍阻断。

请求：同上，用户明确要求“这次把索引也一起更新”。

验收：按对应语言 SUMMARY 增量更新子索引，移动页面复用有效摘要，正文实质变化时核对语义；章节路由变化才改 llms.txt。选中的索引与正文一起暂存并重新检查，未暂存修复仍显示建议。新旧两端同步包含选中的索引改动；不自动更新品牌事实文件或修复历史遗漏。

请求：英文新增 Use Cases 页面，或中文新增未知章节。

验收：Use Cases 对应 llms-scenarios.txt；公开链接不含 Gerrit 语言根。未知章节给出补充映射建议，未选索引维护时可直接继续提交；选择更新后先明确映射再写入。中英文各自索引不能混用，英文进入独立 singdata-docs-en。结构检查通过不表示官网已上线或摘要事实已验证。

## 仅预览原文档

请求：用户说“预览 config-datasource.md 看看”，当前目录是旧中文文档仓库。文档含三张 `=640` 图片，另一篇 data-sources.md 有 HTML 表格和颜色标签。

验收：定位准确文件，用 preview_docs.py 的完整文件路径启动或复用本地服务并返回真实 URL；不索要 Gerrit 账号、不 fetch/提交/推送、不改写原 Markdown。三张图应按宽度显示，HTML 表格保留内联样式。浏览器不可用时区分渲染/HTTP 测试与实际视觉验收，不能声称已肉眼检查。手动拖入同目录文件时能定位图片；同名歧义或外部文件提示重新绑定，不猜目录。共享包不含个人路径、会话状态或凭据。
