# 录屏旁白生成 Skill

本 skill 用于录屏结束后的事后总结。录屏期间正常操作，结束后在同一个对话窗口触发即可。

**不要在录屏前引用本文件**，会影响 AI 的操作风格。录屏前只需要让 AI 引用 `录屏前.md` 创建操作日志 Hook。

**适用边界**：本文件只记录录屏结束后的素材清单与镜头脚本生成规则，不收录具体项目复盘、数据查询规则、客户案例或一次性问题处理经验。此类内容应写入对应业务 Skill 或项目复盘文档。

**路径约定**：下文统一用 `<录屏工作目录>` 表示录屏产物保存目录。默认使用当前工作区下的 `./录屏产物/`；若用户在录屏前指定过目录，以用户指定为准。不要写入作者本机绝对路径。

## 触发方式

不要要求用户使用固定结束语。只要用户表达出录屏已结束、想要整理或生成脚本的意图，即可触发本文件的流程。

可识别的典型表达包括但不限于：
- 录制结束、录完了、可以收尾了
- 开始整理刚才的录屏
- 生成素材清单、镜头脚本或录屏后文档
- 我们刚才录了一段视频

若用户表达含糊（如"差不多了""先这样"），先用一句话确认是否结束录屏，确认后再继续。

触发后立即删除录屏操作日志 Hook，避免后续对话继续写入日志。若当前环境无法删除 Hook，提示用户手动停用后再继续。

时间由用户口头告知。如果不记得，省略即可，时间栏填"未记录"。

**输出为以下文件**，全部保存在 `<录屏工作目录>/` 目录下：
- `素材清单-[日期].md`：给剪辑师定位用
- `镜头脚本-[日期].md`：给配音和后期用
- `recording-log.txt`：录屏期间自动生成的操作日志，连同本次生成的文档一起交付

日期格式：`YYYYMMDD`，如 `素材清单-20260623.md`。

录制完成触发本 skill 时，同时读取 `<录屏工作目录>/recording-log.txt`，将其中的时间戳对应到素材清单的每一步操作上。

默认只生成素材清单和镜头脚本两份文档，依次输出，中间用 `---` 分隔。

### 第一份：素材清单（给剪辑师定位用）

**作用**：剪辑师拿着这份清单，对照原始录屏逐步标注，知道每一段在干什么、属于哪个分镜。

顶部先输出时间信息块：

```
录制日期：YYYY-MM-DD
录制开始：HH:MM（北京时间）
录制结束：HH:MM（北京时间）
总时长：约 X 分钟
素材文件名：（由用户填写）
```

然后按操作发生顺序，逐步列出：

```
### [序号] [操作简称]
所属分镜：分镜 N —— [分镜名称]
用户发问：[用户原话]
AI 执行：[执行的命令或操作，完整写出]
执行结果：[结果摘要，如"返回 20 行数据"、"报错后重试成功"、"写入完成"]
画面特征：[剪辑师在视频里找到这一段的关键画面描述，如"终端出现三列表格，第一行是 customers"]
剪辑备注：[加速 / 保留 / 跳过 / 重点 / 切浏览器]
```

**剪辑备注说明：**
- `保留`：正常速度剪入成片
- `重点`：建议慢放或停留，是核心亮点
- `加速`：建议 2-3 倍速，内容有但不需要细看
- `跳过`：建议剪掉，不影响理解
- `切浏览器`：此处需要切换到浏览器界面，说明切到哪里

### 第二份：镜头脚本（给配音和后期用）

**作用**：对应最终成片的结构，每个分镜写清楚旁白、时长、画面描述。AI 后续改脚本时读这份。

**所有视频的核心传递信息（写旁白前必须理解）：**
> 这系列视频的目的不是炫技，而是告诉用户：你过去需要自己动手做的那些数据操作，现在交给 agent 就可以完成，操作方便，结果也很好。镜头重心在"用户只说了一句话，agent 就帮他做完了"，而不是在展示某个技术本身有多复杂。旁白要让观看者感受到"原来这件事现在这么简单"，而不是"原来这个技术这么厉害"。

顶部先写一句视频概述：
> 本视频演示 [主题]，面向 [目标观众]，成片目标时长 X 分钟。

然后按分镜输出：

```
## 分镜 N：[分镜名称]

对应素材：第 X - X 步（素材清单序号范围）
估算时长：X 秒

画面描述：[该分镜在成片里呈现的画面，一两句话]
旁白：
[旁白文字，按 3.5 字/秒估算，需撑满时长]
```

最后附时长汇总表：

| 分镜 | 名称 | 对应素材步骤 | 估算时长 |
|------|------|------------|---------|
| 1    |      |            |         |
| ...  |      |            |         |
| 合计 |      |            | X 分 X 秒 |

## 旁白写法规范

**目标观众**：有一定数据工作经验、但不一定懂技术细节的人。他们知道"数据查询""数据同步"是什么，但不需要他们理解 SQL 语法或命令行参数。旁白要让这类人看完觉得"这个工具我能用，而且挺方便的"。

**写法规则：**
- 主语用"agent"或"我们让 agent"，不用"AI"或"系统"
- 只描述画面里发生了什么，不解释技术原理
- 字数与时长匹配：3.5 字/秒，30 秒需约 105 字
- 每个分镜旁白必须覆盖该分镜内所有保留/重点的素材步骤
- 避免出现命令参数（如 `--sync`、`--write`）、报错信息、技术术语堆砌

**反例对比（按此标准检查每段旁白）：**

错误写法——聚焦技术细节：
> "我们执行了 `cz-cli table describe` 命令，加上 `--format table` 参数，返回了 customers 表的 DDL 结构，包含 4 列字段定义。"

正确写法——聚焦用户价值：
> "我们让 agent 看一下这张客户表长什么样。它直接把字段结构和样例数据都拿出来了，不需要打开任何界面。"

## 分镜划分规则

AI 根据对话内容自行判断分镜边界，依据以下原则：

**合并为同一分镜的情况：**
- 同一个用户意图下的连续操作（如"看表结构"涉及的 describe + preview + stats 三步）
- 一问一答后紧接着的"确认执行"
- 报错后立刻重试并成功，视为同一操作

**报错重试步骤的处理：**
- 素材清单中须单独列出报错步骤，执行结果写"报错"，剪辑备注标"跳过"
- 紧接着的重试步骤单独列出，执行结果写"重试成功"，剪辑备注标"保留"
- 目的是让剪辑师知道这两步是连续的，中间有一个错误片段需要剪掉，不要误以为是两个独立操作

**用户确认类消息的处理：**
- "好"、"确认"、"可以"等用户确认消息，若发生在写入、删除等高风险操作之前，须列入素材清单
- 用户发问写用户原话，AI 执行写"等待用户确认后执行 [操作名]"，剪辑备注标"重点"
- 这类片段体现 agent 在关键操作前主动等待确认的安全机制，是成片亮点之一
- 纯闲聊消息（与操作无关）不列入素材清单

**单独列为一个分镜的情况：**
- 用户切换了明显不同的操作目标（从"查数据"变成"改数据"）
- 出现了需要切换到浏览器界面的时机
- 有明确的"亮点时刻"需要单独放大展示（如 Time Travel、写保护拦截）
- 开场标题卡和收尾标题卡各自单独一个分镜

**分镜数量参考：**
分镜数量由录屏时长和内容密度决定，没有固定数字。原则是每个分镜有清晰的单一主题，观看者能一眼知道这段在干什么。通常每个分镜对应成片 20-45 秒，太短会切碎、太长会失焦。

## 时间来源规则

- 用户口头告知了时间 → 直接用，不要修改
- 用户没有口头告知 → 读取 `<录屏工作目录>/recording-log.txt`，取第一条记录的时间作为开始时间，取当前系统时间作为结束时间，计算总时长
- recording-log.txt 不存在或为空 → 填"未记录"，不要自行推算或编造
